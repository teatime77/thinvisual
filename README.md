# thinvisual
HTML-over-the-wire applications with a GUI designer

## 開発環境

- Node.js 24以上（npm付属）
- TypeScript / Express / htmx / ts-morph

PowerShellでリポジトリのディレクトリを開き、実行します。

```powershell
npm.cmd ci
npm.cmd run dev
```

ブラウザーで http://127.0.0.1:3000 を開くと、備品管理アプリが表示されます。
追加・在庫数の増減・不足品の絞り込みは、サーバーが返すHTMLで一覧を更新します。
「デザイナーモードへ」から、同じ画面内で表示設定を編集できます。
htmxはローカルのnpmパッケージから配信します。

開発中は `tsx watch` がTypeScriptの保存を検知してサーバーを再起動します。
ブラウザーは手動で再読み込みしてください。Viteによる自動反映は後続の実装で追加します。
GUI設定の `src/app/design.ts` はサーバーがファイルとして読み込むため、
GUIからの保存では再起動せず、備品データを保持したままHTMLを更新します。
このファイルをIDEで手動編集した場合は、ブラウザーを再読み込みすると反映されます。
停止するには `Ctrl+C` を押します。

ポートを変える場合は、起動前に `$env:PORT = '3001'` のように指定します。
サーバーはローカルPCの `127.0.0.1` で待ち受けます。

## チェックとビルド

```powershell
npm.cmd run verify
npm.cmd start
```

`verify` は型チェック・JavaScriptへのビルド・HTTP経由の自動テストを実行します。
テストでは追加・増減・不足判定・不正入力・HTMLエスケープ・通常のフォーム送信を確認します。
デザイナーの保存・部品操作・競合検出・無効な設定の拒否も、一時ファイルとHTTP経由で確認します。
型解析、現在値表示、データの割り当てと表示条件、型の不一致の拒否も確認します。
テストは実際の `src/app/design.ts` を変更しません。
`start` はビルド済みの `dist/server.js` をNode.jsで実行します。
ブラウザーでの操作確認は別途行ってください。

## 現在の範囲

備品管理の通常画面、デザイナーモード、型情報付きデータインスペクターを実装しています。

- 備品名・在庫数・最低在庫数を入力して追加できます。
- `−1` / `＋1` で在庫を変更できます。在庫は0未満にできません。
- 在庫数が最低在庫数より少ない場合に「補充が必要」と表示します。
- 「在庫が少ない備品だけ表示」で一覧を絞り込めます。
- 不正な入力は赤色で表示し、データを変更しません。

データはメモリ上で保持します。ブラウザーの再読み込みでは保持されますが、
開発中のコード保存によるサーバー再起動や、プロセス停止で初期データへ戻ります。
複数のブラウザーは同じデータを共有します。他のブラウザーでの変更は再読み込みすると反映されます。
備品データのDBへの永続化は後続の実装です。

## デザイナーモード

1. `npm.cmd run dev` で起動し、「デザイナーモードへ」を選びます。
2. 部品一覧、またはプレビュー内の表示項目をクリックします。
3. 画面タイトル・カード内の表示文言・一覧のFlex / Grid・間隔を変更し、「保存して反映」を押します。
4. カード内には備品名、在庫数、最低在庫、補充の注意文、固定テキストを追加できます。
   「上へ」「下へ」「削除」で構成を変更できます。カード部品は最大12個です。
5. 「通常モードへ」で通常画面を確認します。設定は再起動しても残ります。

設定は固定の `src/app/design.ts` に、型付きのTypeScriptとして保存します。
GUIはこのファイルだけを書き換え、`logic.ts` と `view.ts` は編集しません。
FlexとGridは同時に設定できず、不正な列数・間隔などは赤色のエラーで表示します。
補充の注意文は、初期状態では手書きの `needsRestock` 関数で表示を判定します。
各部品の表示条件は、登録済みの関数、常に表示、非表示から選べます。

`design.ts` は定められたヘッダーとJSON形式のリテラルに限定しています。
関数本体や任意のTypeScript式を直接記述する形式には、まだ対応していません。
データと表示条件は、`binding: "minimumStock"`、`visibility: "hasStock"` のような名前の参照で保存します。
対応外のコードや矛盾する設定がある場合は、上書きせずエラーにします。
別タブやIDEで設定を変更した後に古い画面から保存した場合も、上書きを拒否します。
再読み込みして最新の設定から編集してください。

`npm.cmd run dev` は `--designer` を指定して起動します。
`npm.cmd start` では保存済み設定を表示するだけで、デザイナー画面・保存用ルートは有効にしません。
ドラッグ操作とViteによる自動反映は今後追加します。

## データインスペクターと表示条件

デザイナーモードの下部に、`Item[]` の件数と、選んだ備品のプロパティ・型・現在値を表示します。
型情報は `src/app/logic.ts` の `Item` と `createInventory().list()`、`visibilityRules` をts-morphで解析して取得します。
現在値はサーバー上の実データです。在庫を増減すると、型情報はそのまま、現在値と関数の判定結果が更新されます。
型解析自体はソースコードを実行しません。表示条件の判定は、サーバーに読み込んだ登録済み関数を実行します。

部品を選択すると、「表示するデータ」と「表示条件」を変更できます。

- 備品名の部品には文字列型、在庫・最低在庫の部品には数値型のプロパティだけを選べます。
- テキスト部品は、固定テキスト、または文字列・数値・真偽値のデータ表示にできます。
- 補充の注意文は固定の文言を表示し、表示条件だけを変更できます。
- 型の不一致や存在しない参照は、保存せず赤色で表示します。
- 選んだ備品は、部品の選択・保存・在庫操作の後も引き継ぎます。

例えば「在庫」部品のデータを `minimumStock` に変更すると、在庫数の代わりに最低在庫数を表示します。
表示条件を `hasStock` にすれば、在庫がある備品にだけその部品が表示されます。
初期状態では `needsRestock` と `hasStock` を公開しています。

関数を追加する場合は、`logic.ts` に書き、`visibilityRules` に登録します。

```ts
export function isEmpty(item: Item): boolean {
  return item.quantity === 0;
}

export const visibilityRules = { needsRestock, hasStock, isEmpty } satisfies Record<string, (item: Item) => boolean>;
```

関数はデータを変更しない同期の判定関数とし、`Item` を1つ受け取り `boolean` を返してください。
`always` と `never` は予約名です。非同期関数や型が非対応の関数は、候補から除外してエラー表示します。
コードを保存した後は、画面を再読み込みしてください。GUIからの割り当て変更は保存直後に反映します。

このPoCでは、`logic.ts` 内に宣言した `Item` インターフェースの直下の単純値を割り当て対象にしています。
配列・オブジェクトは型と概要を表示します。ネストしたプロパティへの割り当てやインスペクターからのデータ編集は未対応です。
通常モードではインスペクターを表示しません。既存のGUI設定はそのまま読み込めます。

## ソースの構成

- `src/app/logic.ts`：備品データ、追加・増減、`needsRestock`による補充判定。
- `src/app/view.ts`：Flexbox / Gridを使う画面とHTML断片の生成。
- `src/app/design.ts`：GUIが保存する画面タイトル、一覧レイアウト、カード部品の設定。
- `src/designer/`：設定の検証・保存・部品操作と、デザイナーのHTML生成。
- `src/designer/types.ts`：ts-morphによる型解析と、ソース変更に応じた型情報の更新。
- `src/designer/bindings.ts`：データの割り当てと型の検証、表示条件の実行。
- `src/designer/inspector.ts`：現在値と型情報を使うインスペクターのHTML生成。
- `src/http.ts`：フォーム受付、HTML応答、通常フォームのリダイレクト。
- `src/server.ts`：ローカル開発サーバーの起動。

現在は `design.ts` のみGUI生成の対象です。手書きの `logic.ts` は、型と登録済み関数の参照に使います。
